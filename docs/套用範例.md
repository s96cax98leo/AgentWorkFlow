# 套用範例：示範客戶 ACME

用一個虛構的客戶與需求，從 init 走到 deliver。客戶、repo、人名、編號全是虛構的。

## 情境

- **客戶**：示範客戶 ACME（一家做線上訂貨系統的公司）。
- **我方**：受託開發，在 ACME 的上游 repo `acme-corp/order-portal` 之外，維護自己的 fork `ourteam/order-portal`。
- **決策者**：使用者本人（本範例稱「你」）。需求方是 ACME 的產品負責人。
- **任務編號**：由上層的任務系統「TaskHub」發，前綴 `ACME-`。
- **需求**：「訂單列表加上『匯出 CSV』按鈕，匯出目前篩選後的結果，最多 1 萬筆；超過時提示使用者縮小範圍。」任務編號 `ACME-042`。

工作區長這樣：

```
~/work/acme/                    # 工作區根目錄（{{WORKSPACE_DIR}}）
├── repos/                      # 我方 clone（{{REPOS_DIR}}）
│   ├── order-portal/           # fork 的 clone，開發目標
│   └── order-portal-vendor/    # 對方交付的參考版本，唯讀（{{FORBIDDEN_REPOS}}）
└── _tpm/
    ├── briefs/                 # 任務單
    └── runs/                   # 每次執行的紀錄
```

## 步驟 0：安裝 plugin（每台機器一次）

```
/plugin marketplace add ~/tools/AgentWorkFlow
/plugin install agent-workflow@agentworkflow
```

## 步驟 1：init

複製設定範本並填值（欄位名稱與格式以 `workflow.config.example` 為準）：

```bash
cp ~/tools/AgentWorkFlow/workflow.config.example ~/work/acme/workflow.config
```

填好的重點欄位：

```
PROJECT_NAME=acme-order-portal
CLIENT_NAME=示範客戶 ACME
WORKSPACE_DIR=~/work/acme
REPOS_DIR=repos
UPSTREAM_REPO=acme-corp/order-portal
FORK_REPO=ourteam/order-portal
FORBIDDEN_REPOS=repos/order-portal-vendor
OUTPUT_LANGUAGE=繁體中文
TASK_ID_PREFIX=ACME-
TASK_AUTHORITY=TaskHub
DECISION_OWNER=使用者
STAKEHOLDER=ACME 產品負責人
BRANCH_PREFIX=feature/
ALLOWED_BRANCH_PREFIXES=feature/,bugfix/,hotfix/
AGENT_NS=agent-workflow:
RUNS_DIR=_tpm/runs
BRIEFS_DIR=_tpm/briefs
ATTRIBUTION_LINE=Assisted-by: Claude
DESIGN_SYSTEM_NAME=acme-ui
```

執行：

```bash
python3 ~/tools/AgentWorkFlow/init.py --target ~/work/acme --config ~/work/acme/workflow.config
```

產生 `.claude/teams/`（rules.md、schemas、tools、golden-set、guard.config.json）、`.claude/workflows/`、`.claude/settings.json`、`CLAUDE.md`、`.mcp.json.example`、`_tpm/runs/`。hooks 預設由 plugin 提供，所以 `settings.json` 裡不註冊 hooks。ACME 需要接 MCP 時再加 `--with-mcp` 重跑，產生正式的 `.mcp.json`。

確認一下：

```bash
cd ~/work/acme
grep -r '{{' .claude CLAUDE.md .mcp.json.example _tpm   # 應該沒有輸出
uv run --no-project --with jsonschema python3 .claude/teams/golden-set/run.py
```

接著打開 `.claude/teams/rules.md` 的「## 專案規則」，補上 ACME 專屬的事：目標 repo 是 `repos/order-portal`、`repos/order-portal-vendor` 唯讀、審查照 fork 裡的 `REVIEW.md`、設計系統 skill 是 `acme-ui`、本機驗證指令是 `make verify`。

## 步驟 2：提出需求

在 `~/work/acme` 開 Claude Code：

```
/sdlc ACME-042：訂單列表加「匯出 CSV」按鈕，匯出目前篩選結果，上限 1 萬筆，超過時提示縮小範圍
```

主 session 先列計畫：

> **計畫（待你核准）**
> - 事件：需求開發（SDLC），workflow `sdlc-plan`
> - args：repo=`repos/order-portal`、epic=`export-csv`、base=`origin/main`、run_dir=`_tpm/runs/20260105-sdlc-export-csv`
> - 會派：4 個 researcher（需求原文、既有 spec／ADR、程式與契約、上游）、1 個 spec-author、1 個 skeptic
> - 會建：worktree `repos/order-portal/.worktrees/export-csv`、分支 `feature/export-csv`
> - 不可逆動作：本段沒有（不 push、不開 PR）
>
> 要開始嗎？

你回「開始」。主 session 建 run 目錄並執行：

```bash
python3 .claude/teams/tools/save_run.py init _tpm/runs/20260105-sdlc-export-csv \
  --event sdlc --target repos/order-portal --requirement "ACME-042 匯出 CSV"
```

## 步驟 3：plan → 閘門 1

`sdlc-plan` 跑完，主 session 在對話裡列出：

> **閘門 1：intent 核准**
>
> `specs/export-csv/intent.md` 重點：
> - 問題：業務人員要把篩選後的訂單交給倉儲，目前只能逐頁複製。
> - 期望結果：一鍵匯出目前篩選結果；超過 1 萬筆時不匯出並提示。
> - 受影響：訂單列表頁、訂單查詢 API。
>
> skeptic 的質疑（2 則）：
> 1. intent 寫了「支援 Excel 格式」，需求原文只有 CSV → 已建議刪除（偷渡範圍）。
> 2. 「目前篩選結果」是否包含排序？原文沒寫。
>
> 待決問題（blocking）：
> - 匯出是否要包含使用者隱藏的欄位？
>   - A. 只匯出畫面上可見的欄位（建議：符合「目前看到的結果」）
>   - B. 匯出所有欄位（代價：可能匯出不該給倉儲看的價格欄位）

同時推播手機：

```
[acme-order-portal] export-csv 閘門 1：intent 待核准
待決：隱藏欄位要不要匯出？A 只匯出可見欄位（建議）／B 全部
另：skeptic 建議刪掉 Excel 格式
回覆「核准 A」或「調整：…」
```

你在手機回：「A，刪掉 Excel。排序照畫面。」

這是**調整**，不是單純核准。主 session 先請 spec-author 修 intent（刪 Excel、補排序照畫面），再把修改後的重點列一次。你回「核准」後才記錄：

```bash
python3 .claude/teams/tools/save_run.py approve _tpm/runs/20260105-sdlc-export-csv plan \
  --by "使用者（手機回覆：選 A、刪 Excel、排序照畫面；修正後核准）" --at 2026-01-05T10:40:00+08:00
```

## 步驟 4：design → 閘門 2

`sdlc-design` 產出 design、spec、plan、progress 與子任務：

| 子任務 | kind | owns | depends_on |
|---|---|---|---|
| `tests` | test | `e2e/orders/export.spec.ts`、`services/orders/tests/test_export_acceptance.py` | — |
| `backend` | code | `services/orders/export.py`、`services/orders/routes.py` | tests |
| `frontend` | code | `web/src/pages/orders/ExportButton.tsx`、`web/src/pages/orders/OrderList.tsx` | backend |
| `docs` | doc | `docs/api/orders.md` | backend |

主 session 列出：

> **閘門 2：spec＋plan 核准**
> - 驗收條件 5 條（default profile 的 EARS 句型），例如「當篩選結果超過 10,000 筆時，系統應顯示『請縮小範圍』，且不產生檔案」。
> - 子任務 4 個，分 3 層：tests → backend → frontend＋docs（平行）。
> - 兩個 analyze：coverage 全部對上；plan 發現 `OrderList.tsx` 也被列在 `backend` 的影響系統表 → spec-author 已改成只屬於 `frontend`。
> - 不可逆動作：本段沒有。

你回「核准」，記錄 design 閘門。

## 步驟 5：build（沒有閘門）

- **Red**：acceptance-tester 寫 5 條驗收測試，跑一次全部失敗，失敗理由是「找不到匯出按鈕」與「端點 404」，符合預期。合進 `feature/export-csv`。
- **第 1 層**：backend implementer 在 `.worktrees/export-csv--backend`（分支 `feature/export-csv--backend`）實作，API 相關測試轉綠。
- **第 2 層**：frontend 與 docs 平行，各自 worktree。
- **Integrate**：integrator 依序 `merge --no-ff`，沒有衝突，`make verify` 全綠，清掉子任務 worktree。

途中 backend implementer 回 `needs_decision`：上游的 `tests/test_routes.py` 逐字比對路由清單，新增端點會讓它失敗。選項：

- A. 把匯出端點註冊在另一份路由設定（`routes_export.py`），避開比對（建議；不改上游測試）
- B. 修改上游測試的預期清單（要走例外核准）

你選 A，不需要例外。

## 步驟 6：test → 閘門 3

> **閘門 3：結果確認**
> - verifier：pass 4、not_verifiable 1（AC-5「1 萬筆在 3 秒內完成」本機沒有足夠的測試資料）
> - 反作弊：無發現
> - design-review：按鈕在窄螢幕被截斷（Important）→ 已在修正輪 1 修好，重驗 pass
> - security-review：匯出端點沿用列表的權限檢查，無發現
>
> AC-5 怎麼處理？
> - A. 接受 not_verifiable，在 PR 說明註明，交 ACME 在測試環境驗（建議）
> - B. 先產生 1 萬筆假資料再驗（代價：多一個子任務，約要動種子資料腳本）

你回「A」。記錄 test 閘門，note 寫「AC-5 not_verifiable，交 ACME 驗」。

## 步驟 7：deliver → 閘門 4

`sdlc-deliver` 四軸審查共 6 則，skeptic 推翻 2 則，保留 4 則（1 Important、3 Nit）。writer 產出 `pr-description.md` 與 `執行紀錄.md`，`check_rules.py --audience external` 通過（PR 說明不出現 `ACME-042` 這類內部編號）。

> **閘門 4：推送與 PR**
> - 要推：`feature/export-csv` → `ourteam/order-portal`
> - 推前檢查：diff 不含機敏值（`grep -qF -f` 比對結果：沒有）
> - PR 說明草稿：`_tpm/runs/20260105-sdlc-export-csv/pr-description.md`
> - 要推送到 fork 嗎？開 PR 到上游另外再問。

你回「推 fork，PR 先不開」。主 session 執行：

```bash
git -C repos/order-portal push origin feature/export-csv
```

開 PR 到上游 `acme-corp/order-portal` 要等你另外同意，agent 不合併、不核准。

## 步驟 8：收尾

- `執行紀錄.md` 列出：產出、驗證結果、跟計畫不同的地方（路由改放另一份設定）、刻意沒做的事（Excel 格式）、未能確認（AC-5 效能）、衍生工作（「超過 1 萬筆時改背景匯出」，不編號，交 TaskHub）。
- epic worktree 保留，等 PR 合併或放棄後再移除。
- `run.json` 有四個閘門的核准紀錄，可以回查每個決定是誰、什麼時候、根據什麼做的。

## 同一個專案的其他事件

- ACME 上游 main 前進了：`/event 上游 main 前進，看跟 feature/export-csv 會不會衝突` → `event-upstream`，開工與收尾各記一次上游狀態，證明零寫入。
- 週會逐字稿進來：`/event 整理 _tpm/meetings/週會.txt` → `event-meeting`。
- 下週要 demo：`/demo-check repos/order-portal feature/export-csv` → `event-demo-check`，compose 指令一律帶 `-p acme-demo`。
