# 監控與整合

這份文件說明怎麼從外面看一個 run 的進度與成本，以及怎麼接到自己的工具（看板、通知、狀態列、OTel）。

先講結論：

- 想知道「現在跑到哪」：`awf.py watch`。
- 想知道「花了多少」：`awf_cost.py`。
- 想讓別的程式接：讀 `<run_dir>/progress.jsonl`，或設 `progress.notify`。
- 這些都是輔助。它們壞掉、沒開、檔案被改，流程與閘門都不受影響。

## 五種看法

| 做法 | 指令或檔案 | 適合 |
|---|---|---|
| 看一次 | `python3 .claude/teams/tools/awf.py watch --run <run_dir> --once` | 人想知道現在的狀態 |
| 快照（JSON） | 同上加 `--json` | 腳本定時查詢 |
| 事件流 | `awf.py watch --run <run_dir>`（長駐），外部程式讀 `<run_dir>/progress.jsonl` | 看板、通知、紀錄 |
| 狀態列 | `awf.py statusline` | Claude Code 畫面下方常駐一行 |
| 成本 | `python3 .claude/teams/tools/awf_cost.py --project . --run-dir <run_dir>` | 段結束後看 token 與時間 |

閘門狀態另有 `save_run.py status <run_dir> --json`（狀態、下一步、等哪個閘門、各段派工與缺件）。watcher 的快照就是它加上 agent 的即時資料。

## watcher 讀什麼

三個來源，全部唯讀：

1. `run.json` 與各段結果：段開始、存檔、等核准、核准、結束。
2. 執行紀錄檔 `<run_dir>/<段>/<label>.md` 的出現：哪個 agent 交件了。
3. Claude Code 的 workflow transcript：哪些 agent 在跑、用哪個模型、目前幾個 token、最後活動時間。

第 3 項的格式官方沒有承諾穩定。讀不懂時，事件只少了 token 與模型，watcher 不會中斷。

## 事件流

長駐執行：

```bash
python3 .claude/teams/tools/awf.py watch --run <run_dir> [--interval 5] [--stall-seconds 900]
```

- 每隔 `--interval` 秒看一次，把新發生的事附加到 `<run_dir>/progress.jsonl`，一行一個 JSON。
- 記憶放在 `<run_dir>/.watch-state.json`。watcher 重開不會重複記同一件事。
- 格式定義在 `.claude/teams/schemas/progress-event.schema.json`。每筆都有 `v`（格式版本）、`seq`（從 1 連續遞增）、`at`（UTC）、`type`、`run`。

| type | 意思 | 主要欄位 |
|---|---|---|
| `run_state` | 整個 run 的狀態變了 | `state` |
| `stage_started` | 某段的 workflow 開始跑 | `stage`、`workflow` |
| `stage_saved` | 某段的結果存檔了 | `stage`、`status` |
| `waiting_gate` | 等人核准 | `stage` |
| `stage_approved` | 核准了 | `stage`、`by`、`kind`（human 或 policy） |
| `record_written` | 某個 agent 的執行紀錄出現了 | `stage`、`label` |
| `agent_started` | 某個 agent 開始跑 | `label`、`role`、`model` |
| `agent_progress` | 同一個 agent 每多 5 萬 token 記一筆 | `label`、`tokens`、`requests` |
| `workflow_finished` | workflow 結束 | `wf_run`、`status` |
| `workflow_stalled` | workflow 沒結束，卻超過 `--stall-seconds` 沒有任何 agent 有動靜 | `wf_run`、`idle_seconds` |
| `watch_note` | watcher 自己的說明（例如 transcript 讀不懂） | `status` |

外部程式的讀法：

```bash
tail -f <run_dir>/progress.jsonl            # macOS、Linux
Get-Content <run_dir>\progress.jsonl -Wait   # Windows PowerShell
```

`at` 是 watcher 看到這件事的時間，不是事情發生的精確時間。要精確時間請看 `run.json`。

### 停住的 workflow

帳號額度用完或網路斷線時，workflow 不會失敗也不會結束，agent 只是停住。watcher 發現超過 `--stall-seconds`（預設 900 秒）沒有動靜就寫一筆 `workflow_stalled`。它只回報，不會自己停掉或重跑 workflow。

處理方式：在主 session 停掉那個 workflow，再跑 `awf.py next`。同一個 session 會帶 `resume_from`，已完成的 agent 不重跑。

## 通知（預設不啟用）

在 `methodology.json` 加：

```json
{
  "progress": {
    "notify": {
      "command": ["python3", "tools/notify.py"],
      "events": ["waiting_gate", "workflow_stalled"]
    }
  }
}
```

- `command`：每個事件呼叫一次，事件內容用 JSON 從標準輸入傳進去。可以寫陣列，也可以寫一個字串。
- `events`：只送這些類型。不寫就全部送。
- 只送白名單欄位：`v`、`seq`、`at`、`type`、`run`、`stage`、`status`、`state`、`by`、`kind`、`label`、`role`、`model`、`tokens`、`requests`、`idle_seconds`、`workflow`、`wf_run`。需求內容、摘要、問題、路徑都不送。
- 內容看起來像機敏值（token、金鑰、密碼）時，整筆不送，並印一行警告。
- 指令逾時（10 秒）或失敗只警告，不影響 watcher 與流程。

指令由 watcher 執行，所以要有人開著 `awf.py watch` 才會送。指令做什麼由你決定，例如發到自己的聊天室或桌面通知。模版不內建任何外部服務。

## 狀態列

在專案的 `.claude/settings.json` 或自己的設定加：

```json
{
  "statusLine": {"type": "command", "command": "python3 .claude/teams/tools/awf.py statusline"}
}
```

顯示最近動過的 run，例如：

```
20261112-sdlc-export · build · 3/5 · 停下了
```

依序是 run 名稱、目前的段、已交件數／派工數、是否等核准或停下。沒有進行中的 run，或任何地方出錯，就印空白，不會讓狀態列壞掉。

狀態列的設定方式見 Claude Code 文件：<https://code.claude.com/docs/en/statusline>。

## 成本

```bash
python3 .claude/teams/tools/awf_cost.py --project . --run-dir <run_dir> [--json]
```

讀 workflow transcript，依 requestId 去重後，依段、角色、模型加總 token（input、cache 讀寫、output）、請求數、平均 context、時長。transcript 讀不懂時明說「這版格式讀不了」，exit 0。

## OpenTelemetry

Claude Code 自己可以輸出 OTel 的 metrics 與事件。模版不實作 exporter，照官方文件開啟即可：<https://code.claude.com/docs/en/monitoring-usage>。

要把 OTel 的資料對回某個 run：

1. `run.json` 的 `stages.<段>.wf_run` 記著那一段的 workflow run id（`wf_…`），`progress.jsonl` 的 `stage_started`、`workflow_finished`、`workflow_stalled` 也帶 `wf_run`。
2. OTel 資料裡 workflow 相關的屬性有 `workflow.run_id`。用它和第 1 點的值對起來。

屬性名稱與有哪些欄位以官方文件當下的版本為準；workflow 的說明見 <https://code.claude.com/docs/en/workflows>。

hook 的輸入沒有 token，也沒有 workflow run id，所以模版不用 hook 做進度回報。

## 不影響閘門

- `save_run.py`、`publish.py`、`merge_gate.py` 都不讀 `progress.jsonl` 與 `.watch-state.json`。`save_run.py --selftest` 有一個案例：把這兩個檔改成假的核准事件，判定結果不變。
- watcher 不寫 `run.json`，也不寫任何閘門資料。
- 所以事件流只能拿來「看」。要判斷能不能推送或合併，請用 `save_run.py status` 或各工具自己的判定。
